# タブ内で完結する作業設計

2026-10-02。Figmaの設計と操作例。アプリの実装・実連携・公開処理ではない。

## 情報設計

主要8タブは「今日・戦略・コンテンツ・エージェント・カレンダー・分析・製品コンテキスト・連携」。サイドバーは移動先、中央はそのタブの作業場所。行やカードを選択すると右ペインを更新し、一覧は残す。コンテンツの原液/X/記事/動画、エージェントの設定/実行ログ/結果、分析の成果/SEO/GEOはローカルな切り替え。

短い入力・接続・実行確認はオーバーレイ。閉じると元の選択、スクロール、フィルター、フォームを保持する。AI相談も作業画面の上に開く。別タブへ移動するのは利用者が明示的に目的を変えた場合のみ。

状態は workspaceId + tab + selectedEntityId + localView で管理。ワークスペース切り替え前に編集内容を退避し、データ・接続・ジョブ・権限・通知・利用量を混在させない。URLにはタブと選択対象を反映してブラウザーの戻る/進むに対応する。

## 起動・読み込み・実行

| 状態 | 表示・操作 | 完了・失敗時 |
|---|---|---|
| セッション未確定の起動 | 小さなロゴと準備状況。広告コピーや装飾アニメなし | セッション確定後すぐにシェル。意図的な最低表示時間なし |
| 通常のタブ移動 | シェルと前のデータを保持。300msを超える読み込みだけ対象領域のスケルトン | 読み込み後に領域のみ更新。選択位置を維持 |
| 読み込み長期化 | 10秒程度で接続確認・再試行。処理中の理由が分かれば表示 | 取得済み情報と失敗部分を分ける |
| AI生成・サイト取り込み | 実際の段階・完了件数、停止、別作業の継続 | 完了分を即利用可能にする。失敗分のみ再実行 |
| 動画レンダリング | 待機→素材処理→生成→書き出し。ジョブを閉じても継続 | 通知・実行履歴・同じ動画タブから再開 |
| 保存 | 未保存→保存中→保存済み。800msの入力停止で送信 | 失敗は本文を保持して再試行・コピー。既存内容を消さない |
| 公開送信 | 重複操作を抑止し、送信中と外部受付を分ける | 結果不明は投稿ID等を照合。確認せず同じ投稿を再送しない |

進捗率や残り時間は実測できる場合だけ表示する。Figmaの起動0.8秒→スケルトン1.2秒はデモの自動遷移で、実装に待ち時間を強制する要件ではない。

## カレンダー

- 2026年10月の曜日に整合した月表示、10月5–11日の週表示、前後月、今日、媒体・状態フィルター。
- 予定の本文、アカウント、日時、タイムゾーンを右ペインで編集。予約済みには変更・取消を表示。
- 空き日付の選択は、その日付を予約フォームに引き継ぐ。FigmaでもSTRING変数で日付→フォーム→確認に伝達する。
- ドラッグ＆ドロップは変更前/後・タイムゾーンを確認してから確定。キーボードでは「日時を変更」で同じ操作が可能。
- 過去日時、存在しない夏時間の時刻、夏時間の重複時刻、期限直前の予約、同時刻の競合を検証。重複時間帯は選択可能なオフセットを明示する。
- 公開成功は外部投稿URL・実行時刻を保存。失敗は理由と復旧手段を表示。接続切れは保留し、再接続だけで過去の予約を即公開しない。
- 制作中・下書き・承認待ち・予約済み・公開済み・失敗は文字でも識別。色だけに依存しない。

## インテグレーション

| 種類 | 画面で確認する内容 | 要件 |
|---|---|---|
| X | アカウント、投稿権限、接続状態、予約 | ユーザー認証で投稿。媒体の制限を公開直前に検証 |
| LinkedIn | 個人/企業ページ、対象アカウント、役割 | 必要なアクセスとページ権限を区別。接続可能な対象のみ表示 |
| WordPress・CMS | サイト、著者、タイトル/本文/画像のマッピング、既定の下書き | 新規下書きと既存更新を区別。CMSごとに認証方法と能力を実装 |
| GA4・Search Console | Googleアカウント、プロパティ/サイト、読取権限、同期日時 | 未取得と0を区別。表示期間・タイムゾーン・遅延を明示 |
| GitHub | リポジトリ、ブランチ、パス、読み取り/PR作成権限 | 対象範囲を限定。資料読み取りとコード変更の権限を分ける |
| 動画プラットフォーム | 書き出し形式、投稿文、サムネイル、公開手段 | 現段階の設計は書き出し/手動公開。API権限を未検証のまま直接公開可能と表示しない |
| 通知・会話 | 接続先チャットと通知対象 | 失敗・承認待ち・完了を選択。接続解除後は通知を停止 |

接続フローは未接続→外部認証中→アカウント確認→接続済み。中止、ポップアップ終了、権限不足、対象なし、期限切れ、取り消し、サービス障害を扱う。OAuth callbackは元のタブ・フォームに戻す。状態とnonceを検証し、別ワークスペースへの誤接続を防ぐ。接続解除前に影響する予約を示し、下書きは残す。

資料確認： [X Create Posts](https://docs.x.com/x-api/posts/create-post)、[LinkedIn Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api)、[GA4レポート](https://developers.google.com/analytics/devguides/reporting/data/v1/basics)、[WordPress Posts](https://developer.wordpress.org/rest-api/reference/posts/)。ここから直接投稿・投稿先権限・プロパティ選択・下書き状態の分離を設計した。アプリ登録、審査、料金、利用権限、各CMSの実装は未完了。

## 細部の操作

- Hover 120ms、押下即時、ペイン変更180msを目安にする。動きを減らす設定では位置アニメを省略。ガラスは補助コントロールに限定し、本文と入力面は不透明。
- 選択中・hover・focus-visible・disabled・loadingを区別。読み込み中でもボタン幅を維持。無効理由は近くに表示し、ツールチップだけにしない。
- Escで閉じ、起点にフォーカスを返す。モーダルはフォーカスを内部に保持。開いている間は背面を操作対象から外す。成功通知は読み上げ、重要な失敗は自動消去しない。
- Cmd/Ctrl+S、選択箇所へのAI編集、変更比較、適用、取り消し、入力中の自動保存を扱う。AIの再生成で手動編集を上書きしない。
- 未保存で破棄される場合のみ離脱確認。保存競合はローカル/最新/比較を提示し、強制上書きしない。
- 検索0件は条件を解除できる。初回の空状態は最初の作成操作を示す。権限不足は「権限を依頼」、接続不足はその場の接続操作。
- UI言語切り替えでタブ、ワークスペース、未保存内容を維持。制作言語は独立。日付表示はUIロケール、予約時刻は選択タイムゾーンで扱う。

## 試作の検証と限界

月→週→月の切り替え、空き日付から予約フォームのオーバーレイ、10月8日のフォームへの引継ぎをFigmaのブラウザープレゼンテーションで確認。主要画面は画像で確認し、全画面の範囲とクリッピング、リンク先の存在を機械検査する。

Figmaは代表データを用いた設計試作。全フォームの自由入力、フィルターの計算、任意日付の予定増減、コピー/ファイル生成、OAuth、保存、生成、投稿は実処理しない。任意日付のフォーム表示は動くが、予約完了のカレンダーは代表例（10月5日）。ドラッグトリガーはツールが拒否したため、日時変更ボタンから確認する操作例と仕様で引き継ぐ。Hover/フォーカス・タイミングの全挙動、キーボードの完全な動作は実装時の検証対象。完成したSaaSや全機能実装とは区別する。

## 実装受け入れケース

1. 原稿編集中にUI言語/別タブ/別ワークスペースを変更して戻り、原稿・選択・スクロールを復元。
2. ネットワーク切断後に入力を継続し、復旧時に重複なく保存。競合時には自動上書きを防止。
3. 月/週の同一イベントが一致し、タイムゾーンを変えてもUTC実行時刻が一致。
4. 予定を移動して取消/確定、予約解除、過去日時/夏時間入力を検証。
5. 接続拒否・中止・失効・別アカウント・権限不足でも原稿と予約を保持。
6. APIが投稿を受理した直後に応答が消失しても、照合して二重投稿を防ぐ。
7. 生成が部分成功しても完成分を編集可能。停止後の課金/実行状態を実際の外部結果と整合。
8. スクリーンリーダーで進捗/保存失敗を認識でき、キーボードのみで同じ主要操作を完了。
